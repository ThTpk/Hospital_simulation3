# จำลองการทำงานในโรงพยาบาล 3 มิติ — รุ่นที่ 3

อาคารโรงพยาบาล 4 ชั้นที่**ตัดผ่าดูได้** ชั้นลอยแยกจากกัน มีผู้ป่วยเดินทำงานจริงตามโมเดลคิวตัวเดียวกับที่สั่งให้ตัวเลขบน panel ขยับ
เปิดจากไฟล์เดียวก็ทำงาน ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องต่ออินเทอร์เน็ต

รุ่นนี้เป็นการรวมสองโปรเจกต์ก่อนหน้าเข้าด้วยกัน

| เอาอะไรมา | จากไหน |
|---|---|
| **รายละเอียดของแบบจำลอง** — 21 หน่วยบริการ · ชุดคำสั่งแบบความน่าจะเป็น · คลินิกเฉพาะทาง 7 คลินิก · สิทธิการรักษา 5 แบบ · ESI 1–5 · เตียง · ลิฟต์ · เดินออกกลางคัน | [`Hospital_simulation2`](https://github.com/ThTpk/Hospital_simulation2) (รุ่นที่ 2) |
| **การทำงานและมุมมอง** — อาคารเดียวตัดผ่าได้ · ชั้นลอยแยก · สไลเดอร์ปรับสด · สถานการณ์สำเร็จรูป · คลิกตัวผู้ป่วยแล้วตามดูเส้นทาง · เทียบผลทั้งวัน · CSV · พาชมอัตโนมัติ | [`Hospital_Workflow_3DSim`](https://github.com/ThTpk/Hospital_Workflow_3DSim) (รุ่นที่ 1) |

> ข้อความบน panel เป็นภาษาไทย · ป้ายห้องและตัวเลขที่พิมพ์อยู่ในฉาก 3D เป็นภาษาอังกฤษ
> (ตัวสร้างโมเดลอบตัวอักษรเป็น texture ไม่รองรับสระและวรรณยุกต์ไทย — ชื่อไทยจึงอยู่ที่ `sim/shared/th.js` ที่เดียว)

## เปิดใช้งาน

`index.html` คือตัวแบบจำลองทั้งหมดในไฟล์เดียว (three.js ฟอนต์ CSS รวมอยู่ในนั้นแล้ว ไม่พึ่ง CDN)

- **ดับเบิลคลิก `index.html`** ได้เลย
- **GitHub Pages**: commit แล้วเปิด Settings → Pages → Deploy from a branch → root (มี `.nojekyll` วางไว้แล้ว)

แก้โค้ดใน `sim/` แล้ว build ใหม่ด้วย

```bash
node build.mjs
```

ระหว่างพัฒนาให้เสิร์ฟผ่าน http เพราะ ES module โหลดจาก `file://` ไม่ได้

```bash
python serve.py
```

## สีของตัวผู้ป่วยหมายถึงอะไร

| สี | ความหมาย |
|---|---|
| 🔵 น้ำเงิน | กำลังเดินระหว่างหน่วย |
| 🟡 เหลือง → 🔴 แดง | ต่อคิวอยู่ (ยิ่งแดงยิ่งรอนาน แดงเต็มที่ = รอเกิน 45 นาที) |
| 🟢 เขียว | กำลังรับบริการ |
| 🟣 ม่วง | รอผลตรวจ |
| 🟦 ฟ้าเข้ม | นอนเตียง (ER · ICU · หอผู้ป่วย) |

ห้องที่มี**กรอบแดง**ล้อมอยู่คือคอขวดของระบบ ณ ขณะนั้น และมีป้ายบอกใต้หัวเรื่องด้วย

คำอธิบายสีทั้งหมดอยู่ท้ายหน้าจอ และ**สร้างจากค่าสีจริงในโค้ด** ไม่ได้พิมพ์ซ้ำ — แก้สีใน `style.js` แล้วคำอธิบายเปลี่ยนตามเอง จึงโกหกคนดูไม่ได้

**ท่าทางก็มีความหมาย:** สามคนแรกของคิว*ยืน*รอหน้าห้อง ที่เหลือ*นั่ง*เก้าอี้ และเมื่อเก้าอี้หมดคนจะ*ยืนเบียด*กันในทางเดิน — ดูแค่ท่าทางก็รู้ว่าหน่วยนั้นล้นหรือยัง

## หลักการออกแบบ 4 ข้อ

**1. `model.js` คือความจริง · `layout.js` คือพิกัด · ที่เหลือมีหน้าที่วาดสิ่งที่สองไฟล์นั้นบอก**
ไม่มีไฟล์ไหนย้อนไปเขียนสถานะในโมเดล ตัวเลขบน panel กับคนที่เดินใน 3D จึงขัดแย้งกันไม่ได้ (กฎนี้มาจากรุ่นที่ 1 และรุ่นที่ 2 ใช้ต่อ)

**2. จำลองวันทั้งวันก่อน แล้วค่อยเล่นเทป**
`runDay()` รันทั้งวันตอนโหลด (~100 มิลลิวินาที) แล้วบันทึกเป็นไทม์ไลน์ `pose(t)` เป็นฟังก์ชันบริสุทธิ์ของเวลา ลากย้อนกลับจะได้เฟรมเดิมเป๊ะ
**ต่างจากรุ่นที่ 1 ตรงนี้ข้อเดียว:** รุ่นที่ 1 จำลองเดินหน้าไปเรื่อย ๆ สไลเดอร์จึงเปลี่ยนได้แค่อนาคต ส่วนรุ่นนี้เลื่อนสไลเดอร์แล้ว**บันทึกวันใหม่ทั้งวัน**โดยนาฬิกาอยู่ที่เดิม — ซึ่งเป็นเหตุผลที่ panel "เทียบผลทั้งวัน" พูดความจริงได้ เพราะมันเทียบทั้งวันจริง ๆ ไม่ใช่ครึ่งวันหลังที่เหลือ

**3. workflow อยู่ที่เดียว**
ผู้ป่วยไม่ถูกล็อกเส้นทางตั้งแต่เกิด และไม่ถูกตัดสินใจด้วย `if/else` กระจัดกระจาย แพทย์จับฉลาก **ชุดคำสั่ง (order set)** จากกฎที่ประกาศเป็นข้อมูล แล้ว `resolvePlan()` คลี่เป็นลำดับหน่วย
เหตุผลเต็ม ๆ อยู่ใน [docs/SPEC.md](docs/SPEC.md) ข้อ 2

**4. ความสูงของชั้นอยู่ที่ฟังก์ชันเดียว**
`floorLift(floor, k)` ใน `layout.js` คือที่เดียวที่ตัดสินว่าชั้นไหนอยู่สูงเท่าไร ทุกคน ทุกห้อง ทุกจุดบนเส้นทาง และกล้อง อ่านค่าจากฟังก์ชันนี้ตัวเดียว
`k` คือระยะยกชั้น — เลข 1 คือกางออก เลข 0 คือซ้อนกันสนิท การกด "ชั้น 2" จึงเป็นแค่การหรี่ `k` ลงเหลือ 0 แล้วซ่อนชั้นอื่น

```bash
node tests/flow.test.js      # กฎ workflow: พบแพทย์รอบสองครั้งเดียว ฯลฯ   (39 ข้อ)
```

ทั้งหมดเป็นเกณฑ์ตรวจรับ ไม่ใช่ "รันแล้วดูเหมือนถูก" — เช่น `view.test.js` ตรวจว่า
สถานการณ์ "อุบัติเหตุหมู่" ทำให้ผู้ป่วยฉุกเฉินเพิ่มขึ้นจริงในช่วงเวลาที่มันบอก
และตรวจว่าทุกหน่วยในรายการมีชื่อไทย ขณะที่โมเดลยังเก็บชื่ออังกฤษไว้สำหรับป้ายห้อง

## ข้อจำกัดที่ควรรู้

- เป็นแบบจำลองคิวและการไหล **ไม่ใช่**การจำลองการรักษา ไม่มีโรค ยา หรือผลการรักษา
- ค่าตั้งต้นอิงโรงพยาบาลทั่วไปขนาดกลางของไทย **ไม่ได้วัดจากโรงพยาบาลจริงแห่งใด**
  ถ้าจะใช้งานจริงต้องเปลี่ยนที่ `STATIONS` และ `LANES` ใน `sim/shared/model.js`
- สี่ชั้นซ้อนกันจริงและยกแยกเพื่อให้มองเข้าไปได้ แต่ที่มุมกล้อง 30° ชั้นบนยังบังด้านหลังของชั้นล่างอยู่บ้าง —
  นี่คือเหตุผลที่การเลือกหน่วยหรือเลือกชั้นจะ**ยุบกองชั้นลงมาให้เหลือชั้นเดียว** (รุ่นที่ 2 เลี่ยงปัญหานี้ด้วยการวางสี่ชั้นเรียงข้างกันบนพื้น ซึ่งแลกมาด้วยการที่มันไม่เป็นอาคารอีกต่อไป)
- ผู้ป่วยไม่หลบกันเวลาเดิน เดินตามเส้นทางสั้นสุดบนกราฟทางเดิน
- โหมด `ตัดขวาง` ตัดพื้นดินไปด้วย เพราะระนาบตัดเป็นของ renderer ทั้งตัว
- ข้อจำกัดที่เหลืออยู่ใน [docs/SPEC.md](docs/SPEC.md) ข้อ 12

### ตัวเลขที่แก้จากรุ่นที่ 2

รุ่นที่ 2 รายงานว่า "ลดห้องตรวจจาก 19 เหลือ 14 ห้อง ทำให้รอเฉลี่ย 25.8 → 58.0 นาที"
ตัวเลข 58.0 นั้นเกิดจากบั๊ก: ตัวจ่ายคิวปัดจำนวนห้องของ**แต่ละคลินิกแยกกัน** (`round(rooms × cap / 19)`)
ขอให้เปิด 14 ห้องจึงได้จริง 12 ห้อง และขอ 16 ห้องกลับได้ 18 ห้อง — สไลเดอร์กำลังคนโกหกทั้งสองทาง
รุ่นนี้แบ่งห้องด้วยวิธี largest remainder (`apportion()` ใน `model.js`) ขอ 14 ได้ 14 เป๊ะ
ตัวเลขที่ถูกต้องคือ **39.6 นาที** และ `tests/view.test.js` ตรวจว่าสไลเดอร์เปลี่ยนจำนวนห้องได้ตรงตามที่เขียนไว้
